# RepoPilot 前端布局优化计划

制定日期：2026-10-20。本文只安排界面优化，不替代平台七天开发计划。

## 1. 目标与依据

参考 Paper Dashboard PRO 的空间比例、导航、网格、卡片与排版：
https://demos.creative-tim.com/paper-dashboard-pro/examples/dashboard/overview.html

沿用现有 Vue 3、TypeScript、Vite、Vue Router、Element Plus。保留冷灰背景 `#f7f8fa`、白色内容、蓝色主色 `#3765ad` 和用户提供的 logo。使用自己的组件和 CSS 实现，不引入参考站的 Bootstrap、脚本或整套模板。

当前问题：侧栏 190px 容纳长名称；导航中英文说明重复；实时页原生控件与历史页组件风格不一致；连续段落压过主要内容；辅助字过小；页面各自定义容器、边框、内边距。

## 2. 固定边界

- 只修改前端和本计划，不改后端、数据库、模型网关、实验协议、用例、原始报告与 logo 文件。
- 不启动模型、Embedding、Docker、实验或后端全量回归，不要求先启动后端。
- 实时数据库、报告文件、历史归档始终明确区分；断连不加载 fixture 冒充真实数据。
- 执行状态与独立验收分别展示；不合并不同 Benchmark 成功率，不增加没有依据的趋势、费用或效率图。
- 缺失值不显示为零。Dashboard 只在完整的已验证状态分组中求记录数量，不重新计算成绩。
- 后续表单改造必须保留原确认、禁用条件、版本校验、错误处理与写入语义，不因视觉优化弱化业务约束。

## 3. 界面规范

| 项目 | 约定 |
|---|---|
| 侧栏 | 桌面约 240px，可收起；图标加短中文名称；实验工作、资源管理、历史归档分组；详情页依附其列表，不额外放不可点击菜单 |
| 顶栏 | 当前位置、页面名称、数据模式；长口径说明放在内容附近 |
| 页面标题 | 左标题与一句说明，右主要操作；减少重复标题和大块空白 |
| 栅格 | 8px 间距基准；区块间约 24px；卡片内部 20–24px |
| 卡片 | 白底、约 8px 圆角、轻阴影；完整功能一个容器，避免给每段内容套边框 |
| 排版 | 正文约 14px；辅助字约 12–13px；标题约 24–28px；路径、hash 与 ID 等宽，长内容可换行或在专用区域滚动 |
| 状态 | 文字加颜色；加载、空数据、断连、刷新失败保留旧快照各自可辨认 |
| 响应式 | 大屏摘要四列，较窄两列／一列；窄屏侧栏为可关闭抽屉；表格在容器内横向滚动，页面不整体溢出 |

## 4. 分轮交付

每轮交付一个完整可验收模块。当前授权从第一轮实施，后续按相同文档推进；不把第一轮称为全站改造完成。

### 第一轮：公共外壳与实时 Dashboard

1. 导航分组、缩短名称、加入一致图标；实现当前项、父级详情关联与侧栏折叠。
2. 顶栏展示页面位置和数据来源模式，窄屏可打开／关闭导航。
3. Dashboard 改为标题与刷新、四个记录数量摘要、最近实验／最近运行、状态明细、简短使用入口。
4. 数据读取从页面拆出小模块，只 GET `/api/v2/dashboard`；校验来源和字段，处理加载、空数据、断连、超时与刷新失败。
5. 断连时摘要显示“未连接”，不填零；刷新失败时保留上次响应并明确标记“上次读取”，禁止冒充最新数据。
6. 用 Element Plus 统一 Dashboard 的按钮、表格、空态与加载；公共基础样式限定作用域，不批量改写其他页面业务表单。

验收：可从分组导航进入所有原页面；详情父导航正确；四项数量为 Agent 版本、Benchmark 版本、实验、Run 记录数；准备、生命周期、执行、验收保持四个独立维度；fixture 口径说明保留；桌面与窄屏不溢出；断连不出现假成绩。

### 第二轮：实验列表与批次详情

- 将实验选择与创建、运行与配对、比较结果、人工决定、报告导出组织为明确区域／页签。
- 表格工具栏、状态、操作按钮遵循第一轮规范；保留完整对子、覆盖率、门槛、证据不足与不可比说明。
- 人工决定和启动表单逐个完整迁移到 Element Plus，逐项核验原有确认、版本与禁用条件。

验收：从实验选择到比较、人工记录和导出的路线可读；只切换视图不提交请求；不改变成绩与确认规则。

### 第三轮：运行列表、Trace 与证据详情

- 统一列表筛选、运行概况、Trace 导航和证据阅读区；配置与长 ID 放在可展开详情。
- 历史 Diff、测试输出、模型请求与预算说明保留来源及截断提示。
- 审批、取消等现有操作的确认、版本和终态约束原样保留。

验收：能从 Run 定位事件、测试与修改；原始事件和文件快照仍有区别；窄屏日志只在区域内滚动。

### 第四轮：资源、报告与历史页面收尾

- Agent／Benchmark 登记和导入表单、报告文件查看、历史总览／对比使用统一容器与控件。
- 明确 archived 与实时数据；完整来源、口径和历史限制可查。
- 清理被替代的局部样式，核对所有现有路由与空态，不增加新产品范围。

验收：主要页面视觉一致；登记／导入／报告校验的业务语义不变；历史页面和离线数据入口仍可独立使用。

## 5. 验证与记录

每轮执行受影响的前端数据检查、`npm.cmd run typecheck` 和 `npm.cmd run build`，并做页面检查。共享样式变更时抽查一个历史页面和一个实时页面。

真实后端未启动时，优先检查诚实断连页面。成功／空数据／超时／刷新失败可在隔离的本地检查页使用明确标为“界面检查样例”的合成数据；不写入业务数据文件，不放进产品路由，不混入真实实验统计。真实页面检查只使用 GET 和导航，不触发实验、登记、导入或审批写操作。启动、取消与人工决定等交互仅在完全替代业务 fetch 的临时检查页用内存响应验证，未声明请求也被该页面拦截；不回退到真实 API。

### 第一轮交付与实际检查

- `App.vue`：240px 分组侧栏、图标、折叠导航、页面位置与数据模式；历史／实时详情分别选中对应父列表。窄屏抽屉可用 Escape 关闭，打开后焦点进入关闭按钮，背景不可交互，关闭后焦点回到切换按钮。
- `workbench.css`：公共布局和第一轮卡片、网格、排版规范。未批量覆盖其他页面的表单与业务样式。
- `DashboardView.vue`：摘要、最近记录、独立状态分布和入口。`LiveDashboard.vue` 只负责编排读取；`data/dashboard.ts` 校验既有 API 响应。
- 当前后端的只读 GET 返回空数据库，浏览器显示“已读取”、真实零数量与空列表；没有启动后端或创建实验来制造数据。
- 临时、显式标注的合成数据页面检查了非空列表、缺失日期、执行成功但验收未知、断连“未连接”和刷新失败“上次读取”。检查页随后删除，没有进入业务路由、业务快照或生产构建。
- 390px 下页面无整体横向溢出；抽屉焦点和 Escape 关闭通过。桌面侧栏折叠仍保留链接可访问名称；历史总览到详情的跳转、父导航、来源模式与页面宽度抽查通过。
- `npm.cmd run test:dashboard`：6 项通过；`npm.cmd run test:snapshots`：21 项通过；类型检查通过。首次生产构建受沙箱 realpath 权限限制，按权限流程重试后通过。检查页面未观察到控制台错误。
- 未进行付费调用、Embedding、Docker、后端全量回归或实验运行；第二至四轮仍待实施。

### 第二轮交付与实际检查

- `LiveExperiments.vue`：列表优先，支持对已加载的最近 50 条按名称／ID 筛选；选择批次保存在 URL，详情分为运行与配对、比较结果、门槛与人工决定、报告导出。保留五秒只读刷新；切换页签不提交写请求。
- 新建实验使用 Element Plus 抽屉和两步表单。只列 ready 固定版本，次数、预算、顺序、干预规则、最多 40 Run、可选质量门槛的原接口字段不变。
- 冻结请求正文与当前编辑条件分开。修改条件后旧预览明确失效，确认及模型许可重置；需要重新预览。启动仍发送原字段、预览 hash、同一请求键、明确确认与模型许可，不自动重试；worker 仍需单独授权。
- `ExperimentComparisonPanel.vue` 保留分组启动口径、完整对子、逐例分类／原因、资源未知与覆盖数、证据引用；墙钟含等待，不冒充模型时延；未增加新的评分或总体收益结论。
- `ExperimentReviewPanel.vue` 保留系统门槛、独立人工身份／理由／确认和追加历史；提交绑定捕获时的比较 hash，读取中、旧 hash、空字段不能提交。模拟 409 显示错误，不覆盖已追加的历史。

### 第三轮交付与实际检查

- `LiveRuns.vue`：当前页用例／Agent／Run ID 筛选、Element Plus 表格、空态、加载和分页；标明每页最多 20 条，不假定总页数。读取失败保留上一页数据并标注上次读取；异步代次校验避免过期响应覆盖页面。
- `LiveRunDetail.vue`：执行阶段、执行结果、独立验收、观测证据分别展示；完整 ID 和时间可展开。详情分为 Trace 与证据、执行与审批、修改与独立评测、模型账本与请求四个页签。

### 第四轮交付与实际检查

- `LiveCatalog.vue`：Agent／Benchmark 均以已登记版本列表为主，支持当前已加载最近 100 条内筛选。登记／导入放入抽屉，版本详情按保存配置与最近校验分区；完整 ID、内容 hash 可展开。Benchmark 仍可查最近 100 条已注册仓库，未改变正式运行的范围、保护测试及基线语义。
- `data/catalog.ts` 拆出原 API、类型、配置生成与提交边界。保留不可变版本、1 MB UTF-8 配置限制、Process／Native 各自字段、显式校验与原请求键；失败不自动重试，失败后刷新再校验沿用原键。断连、读取中、validating 和 interrupted 均不能发起校验；登记不会自动校验。无效本地 JSON 直接提示，不发送请求。
