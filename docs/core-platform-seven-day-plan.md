# RepoPilot 核心平台七天交付计划

周期：**2026-10-12—2026-10-18**。2026-10-11 起草，2026-10-12 确认执行窗口；以下为待实施计划，不代表完成承诺或新增实测结果。

本计划取代上一轮“实验工作台交付计划”的后续开发安排，旧文档保留实际验收历史。当前优先级：**可观测 → 可评测 → 可实验 → 决策支持**。不再重复建设已有 Agent 或扩充展示壳层。

## 1. 统一产品定位与本周交付

**RepoPilot — Coding Agent Evaluation & Experiment Platform**

面向 Coding Agent 开发者、AI Infra 和 Agent Evaluation 团队的可观测、可评测、可实验的质量分析与优化平台。

产品理念：**让 Coding Agent 的每一次改进，都有证据支持。**

用户提供代码任务与 Agent 配置，平台固定任务、环境及预算，明确实验变量，关联执行证据并衡量收益和代价，帮助用户决定采用新策略、保留基线或继续实验。自研 Agent 是当前唯一被评测对象；它与平台的职责逐步分清，不因此立即重写适配框架。

本周交付：在现有工作台上形成一份**有来源、有覆盖率、有配对变化、有失败复核、有决策条件**的实验分析报告，并在已有页面展示。资源缺失、条件不可比、证据不足都能明确表达，不以自动生成肯定结论作为验收标准。

本周不承诺通用成功率提升，不把一次 Trace 当成根因证明；示例中的 70%/80%、Token 和成本数字不得进入真实结果。

## 4. 本周固定的统计口径

### 4.1 任务与测试

- **区分执行状态与评测结论**：completed 不直接作为成功分子。评测保存 passed/not_passed/unknown、规则版本、来源和复核信息，不能改写原任务状态。
- **端到端成功率**沿用 PRD：达到预定义验收要求的运行数 / 已启动的端到端运行数。启动边界采用实际任务开始事件，不以准备文件存在为准；启动前准备失败单列，启动后环境错误、超时、取消保留在分母。
- 运行中或证据未决必须单列；显示暂定成功比例时同时给出已启动、已判定、未知/进行中数量，不能当作最终批次成绩或默默剔除。
- bug_fix 需要修改前失败证据和修改后目标/回归测试通过；feature 需要预定义功能与回归验收；额外 expected_behavior 人工复核有依据。没有证据只能 unknown，不能用模型自评补齐。新增验收定义另起版本，不回写老用例伪装事先约定。
- 结构化测试报告可采用 pytest JUnit XML，从受控容器输出位置读取，保存报告 hash 和 TestRun 关联，不新增第三方测试框架。解析时处理 setup/teardown、skipped、errors，限制文件大小；解析失败不影响保留原始输出。固定验收仍受保护，不能让模型修改报告规则。
- Test Pass Rate 依 PRD 使用最终轮的 passed/(passed+failed+errors+skipped)，同时给出微平均和逐运行全必需测试通过比例；只对有可信计数的运行计算并报告覆盖率。零退出码但漏跑必需测试不能通过验收。
- Recall 继续使用既有标注检索数据集及其版本，保持 Top K 后映射去重规则；独立展示，不把它拼成另一批任务的 Recall，也不自动用 Agent 多轮查询合集冒充首次召回。

### 4.2 Token、成本和时间

- usage 来自供应商实际响应；若不提供或请求超时后无法获取，标记 unknown。失败的模型输出只要返回可验证 usage 也累计；缺失不能当免费。
- 用唯一调用/请求尝试标识去重。研究、规划、候选、反思都纳入运行范围；查询 Embedding 单列，准备期仓库向量化也单列，禁止重复摊入每次任务。
- 总量同时显示已知小计、已记录/实际调用数与完整性。任一调用用量缺失时不能把小计标成完整总量；不能靠字符数推算后冒充真实 Token。
- Cost 是**估算**：保存币种、模型、价格版本/生效日期、单位、输入输出及缓存计价规则；缺价格或用量时总成本 unknown，已知分项另列。本周不爬取实时价格或伪造账单，用户可提供核实过的价格配置。
- 墙钟时长是运行开始到终态，包括人工等待；模型、工具、测试的调用耗时另列。人工等待只在有明确区间时计算，缺少时间戳保留未知。嵌套/并发 span 不直接相加当总耗时；pytest 输出耗时不当 Agent latency。
- 资源均值同时报告有效样本数和覆盖率；小样本以逐例值和均值为主，不用 P95 或百分比包装不稳定结论。

### 4.3 实验与决策

- 任务输入 commit、受保护测试版本、验收规则、模型配置、Prompt 模板、工具定义、镜像身份、预算和恢复规则形成条件清单。模型服务内部版本未知、镜像 digest 不可得等情况显式记录；本地镜像至少记录不可变 image ID，tag 本身不能证明相同环境。
- Prompt 模板版本与运行中动态消息分开；实验策略提示的预期差异要声明。上下文内容、查询与最终修改是输出，不要求双方完全相同。
- 重复运行按预先声明的 repeat_index 配对，保留全部尝试和干预，不挑最好一次。当前不立即建设外部 Agent 适配或大批量队列。
- 质量提升率以“成功率百分点差”表达，同时列改善和退化的用例；Baseline 为 0 时资源相对变化不可算，不显示虚假百分比。
- 决策门槛在新运行前冻结；对老结果事后尝试的阈值标为探索性分析，不能包装成预注册发布验收。门槛记录最小覆盖/样本要求、可接受退化、质量及资源上限；不硬编码普遍适用的通过阈值。
- 规则符合只代表“符合当前任务集和配置的门槛”，不代表统计显著、可泛化或可自动发布。证据不够时输出继续实验。

## 5. 失败分析与下一实验建议

沿用 PRD 的 Failure Taxonomy，不重新发明一套：RETRIEVAL_FAILURE、CONTEXT_FAILURE、PLANNING_FAILURE、TOOL_FAILURE、EDIT_FAILURE、TEST_FAILURE、REASONING_FAILURE、RECOVERY_FAILURE、BUDGET_EXCEEDED、APPROVAL_REJECTED、CANCELLED、UNKNOWN。

本周只为有明确证据的情况添加规则，其他类别由人工复核或保持 UNKNOWN。每条分析保留观测事实、假设、关联事件/TestRun/Diff、来源（规则/人工）、复核状态；一条主要类别和可选次要类别。失败发生节点不等于失败根因。

| 观察与证据 | 可以提出的假设 | 下一步受控实验，不直接宣称有效 |
|---|---|---|
| 相关目标进入候选却未进最终 Top K；需新增可追溯候选证据或离线诊断支持 | 排序可能限制上下文质量 | 同一候选集合对比 RRF 与 Reranker，冻结候选预算并记录额外耗时/成本 |
| 目标进入 Top K，但预算事件证明未送入后续模型请求 | 上下文选择或预算分配不足 | 比较 Context Selection/压缩策略 |
| 正确上下文进入请求，计划经人工核对遗漏验收步骤 | 规划约束可能不足 | 比较 Planning Prompt/结构化检查策略 |
| 首轮失败、已有恢复记录未改善且消耗更多资源 | 当前恢复策略可能低效 | 在相同总预算下比较 Simple Retry 与 Reflection |

**当前保存的是工具返回 Top K 和候选计数，不是完整候选列表。** 仅凭候选数量不能认定相关目标“已在候选中被排掉”；缺这种证据时只能建议先补诊断。上下文多不等于无关内容多，Token 高也不能单独证明噪声干扰规划。

本周交付建议与待验证假设，不默认实现或调用 reranker。只有证据指出排序问题且核心交付已验收，才将 Hybrid+Reranker 排入下一周独立实验；不提前调数据集制造改善。

## 6. 实现分层与进度控制

- `rag` 请求层返回调用结果与观测元数据，调用方将其关联到 task/phase/call_id；使用显式依赖/上下文，不以可变全局变量串联不同任务。
- `services` 负责观测持久化、指标、条件核对、配对及决策；复用现有 TaskEvent/TestRun，不先建立一套庞大 Evaluation ORM。确需 TestRun 增加结构化报告字段时采用兼容迁移，旧值为空。
- `scripts` 仅负责命令参数、文件读写和调用服务；前端复用现有快照投影与三个页面，不在浏览器重新发明统计口径。
- 事件/报告协议明确版本，新增字段可缺省；统计需兼容旧文件，原始历史证据不可修改。观测写入失败要暴露完整性缺口，不静默宣称已采集，也不能触发对已执行业务的重复调用。
- 本周不做：实时操作台、登录多租户、云部署、CI 平台、外部 Agent 框架、跨语言解析、完整消息存储平台、大规模重跑、默认 Reranker、自动根因裁决。
- 每轮完成一个模块后解释用途、数据流和设计；助手写代码，用户执行明确授权的真实模型联调。无需每步确认，不主动调用付费接口或读取秘密。

**赶进度时的取舍顺序**：先砍新图表、报告美化、建议种类和新策略实现；保留资源采集完整性、指标分母、可比性、证据引用和旧数据兼容。第 6 天有未完成核心项时，缩减界面交互继续补核心，不用文档替代代码，也不以截止日期声称验收完成。

## 7. 最终集中验收：只看三件事

1. **能追溯**：一个新运行的模型/Embedding 请求、配置、工具上下文、测试与最终结果可关联；失败和缺失不会消失。
2. **能衡量和比较**：同一数据按固定口径得到一致指标；旧数据未知为未知；条件漂移、退化和未决结果可识别，真实与模拟结果分开。
3. **能帮助判断**：页面从配对结果直达证据，显示质量与资源取舍、门槛结果及下一步假设；不足时明确“证据不足”，不会自动宣布策略更优。
