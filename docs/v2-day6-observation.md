# Day 6：Trace 浏览模块

2026-10-16，本日第一模块已实现；不表示 Day 6 全部完成。

## 本次补齐

过去 Run 页面只能查看事件名称、来源和时间，排查时无法从页面展开调用 ID、检索排名或上下文摘要。本次增加 `GET /api/v2/runs/{run_id}/trace`，Run 详情直接展示该接口的数据。

- `after_sequence` 按平台 RunEvent 序号翻页，`through_sequence` 固定首次读取的末尾序号。运行继续追加事件时，本次翻页边界不漂移；刷新开始新的读取。
- Native 原任务 ID、原事件序号与节点独立展示；平台序号不会被旧 TaskEvent.payload.sequence 覆盖。
- 已存的模型调用、用量、检索结果、上下文 hash、Plan、Reflection 和生命周期字段按允许清单投影。未支持字段只显示元信息；结构不合法明确标 invalid。
- 不公开任意原始 payload、请求参数、认证头或工作区文件正文。单个字符串最多 2,000 字符、数组最多 50 项，每事件标量内容预算 20,000 字符；截断有标识，此接口是浏览投影，不是完整证据导出。
- 时间标注为平台落库时间，Process Agent 的真实事件发生时间没有记录时不推断。能力层级仍由原有后端规则计算，不因显示了 Trace 就升级 L1/L2。
- 展开事件时暂停自动刷新，避免正在阅读的内容消失。原 `/events` 元信息接口保持兼容。

例子：`RETRIEVAL_COMPLETED` 中出现 app.py，只能说明工具返回过该代码。随后 `TOOL_CONTEXT_PREPARED` 若显示 discarded，不能把它算作已接纳的代码上下文。`MODEL_CALL_STARTED.tool_context` 的工具调用 ID、消息索引、hash 和字符数可以用于核对该次请求尝试包含的消息，不能证明模型理解或采纳了内容。本模块展示这些原始摘要，尚未自动生成跨事件关联图。
