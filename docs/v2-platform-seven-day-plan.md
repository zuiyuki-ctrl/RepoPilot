## 1. 本周要演示什么

用户在 Vue 页面完成：

```text
注册 Agent 及不可变版本 → 协议校验 → 导入 Benchmark 清单
→ 选择双方配置并创建实验 → 确认启动 → 审批/查询/取消
→ 查看每次 Run 的平台评测、分级轨迹 → 查看配对差异与证据缺口
```

演示不依赖 Swagger `/docs` 或手工复制运行 ID。数据库、API、worker、Docker 和已有镜像的准备仍可使用终端；“页面闭环”不等于浏览器自动安装运行环境。

最小被测对象为 RepoPilot Native 和独立 Process Demo。Demo 不导入 `backend.app`、不调用内置规划服务；提供明确标为 fixture 的未修复/修复版本。它证明平台能够评测独立程序，不代表通用 Coding Agent 能力。

本周交付是本机单操作者 MVP：单 worker、全局并发 1，复用 Vue 3 / TypeScript / Element Plus / Vite、FastAPI 和既有评测资产。不上公网，不重做设计系统，不新增检索算法。

本周目标统一表述为：**Native + 符合协议的外部无网络 Demo 的页面闭环，以及分级观测的真实展示。** 页面导入的是已准备好的 Agent 运行描述，不是任意源码的自动适配；本周不宣称已支持普通用户的联网 Coding Agent 普遍接入。L0/L1/L2 表示可观察到的证据深度，不是 Agent 能力排名或三档任务评分；L0 可以修复成功，L2 也可以修复失败。

## 2. 先约定“导入 Agent”和“分级观测”

### 2.1 页面接入的含义

- Native：选择平台已实现的内置适配器，登记版本、配置和能力；不能上传任意 Python 对象在 API 进程中执行。
- Process：通过表单或受校验的 JSON 描述导入 Agent 身份、版本、已存在的容器镜像 ID/digest、入口参数数组、协议版本及能力声明。注册后由操作者显式发起无模型费用的协议校验。
- 描述文件只允许声明字段，不携带源码包、密钥、任意主机挂载或 shell 命令字符串。参数接受不等于免除容器资源、文件与网络限制。
- 程序必须实现 `/input/request.json` → `/output/result.json` 协议；已有 Agent 不符合时需要编写适配包装。平台本周不自动适配任意 GitHub 仓库，不自动安装依赖、构建或拉取镜像。
- 首个外部对象为无网络 Demo。调用真实模型的外部 Agent 需要额外的秘密注入和可执行网络出口控制，按 PRD 延后；本周保留现有 Native 的真实模型能力，由用户明确启用。
- Ready 仅代表特定版本/环境的协议校验通过，不代表能修好任务。界面不得显示尚未实现的 HTTP、商业 Agent 或专用 Python Adapter 为可用选项。

### 2.2 分级观测交付标准

| 层级 | 实际证据 | 页面展示 | 本周证明方式 |
|---|---|---|---|
| L0 黑盒 | 平台启停、退出信息、日志、前后快照、独立 Diff/测试、墙钟 | 执行状态与验收状态分开；Diff、Tests、耗时、错误及清理状态 | 独立 Process Demo 的真实容器运行 |
| L1 调用级 | 模型请求、usage、工具调用、结构化错误 | 已知用量、覆盖率、调用列表、来源；有价格才显示估算成本 | Native 的实际调用记录；外部上报解析用明确标记的协议 fixture 验证 |
| L2 上下文级 | 检索、实际选用上下文、计划、反思 | 关联调用的上下文证据与计划；实际发生才显示反思，有版本化标注才计算 Recall | Native 可获得的真实深层记录；未发生的阶段不补造 |

L0/L1/L2 是摘要，不是一个控制采集能力的开关。注册页展示 `declared` 与 `validated`；每次 Run 的各字段展示 `available / partial / missing / unsupported / invalid`。实现时固定摘要推导规则，混合能力仍以字段明细为准，不因出现一条计划事件就把整次运行标为完整 L2。

用户可以选择 Agent 实现支持的采集配置，但不能通过勾选 L2 给不提供轨迹的程序增加能力。外部上报标记 `agent_reported`，平台证据标记 `platform`，适配器映射标记 `adapter`；声明能力和数据可信程度是不同维度。

不提供 usage 的 L0 仍能完成任务评测；Token/Cost 为未知，不填 0。声称提供却漏报为 missing，数据不合法为 invalid，部分记录仅显示已知小计及覆盖率。Process 内部轨迹退出后导入，运行中只展示平台生命周期，不承诺外部实时 Deep Trace。

Day 1 固定版本化的能力字段及摘要推导规则，并由后端统一计算，前端只展示。除了上述完整性状态，另记录阶段是否实际发生及判断依据：有明确证据表明本轮未执行反思时，显示“未发生”，不算反思漏报；应当存在的模型调用缺 usage 时，显示 missing；仅因没有收到事件无法确定是否发生时，保留未知。未知的实际调用总数不能由已收到事件数代替并计算成 100% 覆盖率。

摘要规则须列明各层级所需字段、部分记录如何降级、哪些阶段为条件适用项，以及运行中和终态的差别；注册能力、实际观测层级、完整性和任务验收结果分别保存。Day 6 复用该协议，不临时引入第二套分级标准。

## 5. 每天具体完成什么

### Day 1：通用运行与评测边界

1. 定义版本化 Run、AgentRunRequest/Result、Capability、事件来源与完整性结构，同时固定第 2.2 节的字段、阶段发生状态及分级摘要规则。区分排队/准备/执行/等待审批等生命周期、Agent 执行结果和 Evaluation 结论，不用单个 status 混合三者。
2. 提取平台评测所需输入：Case/规则版本、基线证据、平台最终快照、Diff/保护检查、TestRun/JUnit 引用。协议不能要求 PlanTask、检索或内置 Source ID 存在。
3. 增加最小 Run/事件/评测绑定持久化，明确 TestRun 的旧任务与新 Run 关联及一致性约束。Native 可保存 `legacy_task_id`，Process 不创建假任务。先读现有迁移再决定表结构，旧记录明确 legacy。
4. 建立后续 worker 可复用的状态转换、任务领取与幂等边界，不在请求线程中运行 Agent，不提前生成所有 Registry 空接口。
5. 接入最小 `/api/v2/runs/{id}` 与事件读取，前端建立 live/archived 数据边界、连接失败提示和通用状态显示。

验收：纯输入/模拟运行证明“完成但测试失败”“测试通过但执行失败”“证据缺失”不能错误变成 passed；旧报告不改写。集中检查兼容迁移及关联约束。本日不调用真实模型。

### Day 2：Native Adapter 与人工审批

1. 用 metadata/prepare/run/cleanup 包装既有服务，将通用 Run 与旧 AgentTask 关联；通用 Runner 不导入内置节点或解析内置计划细节。
2. 把计划/候选等待保存成持久检查点及待审批引用；批准、拒绝、取消关联具体检查点和版本。重复请求返回已有结果，过期审批拒绝。
3. 本日落地最小持久 worker，包括数据库领取、执行所有权、检查点恢复和全局并发 1，再接通 Native 执行路径；数据库短事务与模型等待分离。等待审批释放执行槽位，恢复仍需重新领取。无法证明可恢复的中断标为 interrupted/unknown，不自动重发模型调用。Day 3 的 Process 执行和 Day 4 的协议校验复用它，不等到 Day 5 才搭建 worker，也不另用 API 进程内后台任务替代。
4. 从此阶段就映射模型、工具、检索和上下文证据及来源，不到 Day 6 才补采集。cleanup 的失败单列，不覆盖原始异常。
5. Run 页面呈现待审批计划/候选、批准或拒绝、状态变化；API 只负责登记决定，由 worker 继续同一 Run。

验收：模拟模型完成一次暂停/恢复/终止链路及旧流程回归，证明已完成调用/写入不会重复。真实付费演示留到 Day 7 用户显式启用，或单独记录已获授权的联调。

### Day 3：外部 Process 与独立评测

1. 实现已有镜像 ID/digest + 参数数组的容器启动协议；固定 input/workspace/output 位置，限制网络、用户、capabilities、CPU/内存/PID、时间和输出大小，不挂载秘密、Docker socket 或平台数据库。
2. 独立 Demo 实现请求/结果协议，不引用平台业务代码。保留未修复、修复及异常 fixture，输出不能伪造平台评分。
3. 确认容器和所有写入进程停止后安全读取产物，校验路径/链接、大小、版本、run_id 和退出码。支持超时、取消、解析失败后的幂等清理及残留定位。
4. 从平台快照计算修改范围与受保护内容完整性；在新容器使用平台权威测试与配置验收，Agent 提供的 JUnit 只作声明。不得让工作区 pytest 配置/插件控制权威验收命令。
5. 接通可选 usage/trace 的结构校验、来源和缺失状态；L0 不强制向量化。详情页展示真实平台事件、日志限制、Diff 和测试证据。

首版权威测试只支持当前固定 Python/pytest 配置和 task-list 用例，不承诺任意语言、依赖或测试框架。平台控制测试文件来源、pytest 命令、配置文件、工作目录和插件加载策略；明确处理工作区中的 conftest.py、pytest.ini、pyproject.toml 及 PYTEST_* 环境变量，不能只校验测试文件 hash 就声称完成隔离。实现时固定可用插件和导入路径，不兼容的测试配置明确拒绝，不悄悄回退到 Agent 自带的测试命令。该边界须在 Day 3 验收记录中列明，仍不等于对恶意被测代码的完整防作弊保证。

验收：模块集中覆盖 A1—A5；至少真实运行无网络 Demo 的未修复/修复与超时清理，其他异常注明模拟或实测。镜像准备由操作者显式完成，不自动拉取/构建。没验证容器就不写“隔离已验收”。

### Day 4：从页面登记 Agent、导入 Benchmark

1. Agents 页面支持身份/版本登记、Native/Process 选择、描述 JSON 导入、参数字段编辑、能力声明及校验报告；版本标签与内容指纹绑定，不可覆盖。
2. 协议校验作为 worker 的持久操作，由用户点击触发；使用临时 fixture、无真实模型凭据，检查输入、输出、写入边界、终止与清理。不能无费用完成握手的版本不假装 Ready。
3. Benchmarks 页面导入平台支持的版本化清单，查看固定 Case 列表/顺序、提交、可写/保护范围、权威测试环境、必需测试和基线规则。准备状态不能仅靠 JSON 能解析判定。
4. 首套任务复用固定 task-list 用例与 8 项测试，不新做大规模数据集。导入只登记/校验清单，实际运行基线按实验准备执行并保存证据。
5. 通过白名单 API 返回安全展示字段；不向页面传输秘密环境或任意主机路径。提供字段错误、环境未就绪、版本冲突和校验失败的可读提示。

验收：浏览器实际登记 Native 和 Process Demo、执行校验、导入 Suite；未知字段、重复版本不同内容、缺镜像/规则不能成为可运行配置。刷新页面后记录仍在数据库，不靠内存保存。

### Day 5：页面启动实验与批次调度接入

1. 创建实验时选择固定 Suite/Case、两份 Agent 配置、controlled/benchmark、变化字段、重复次数、预算、执行顺序、干预策略及可选门槛。
2. 启动前展示 Run 数、双方差异、可能付费的步骤和证据限制；显式确认后冻结 manifest/hash。配置变化需新建实验，不修改运行中的规则。
3. 在 Day 2 已实现、Day 3—4 已复用的 worker 上接入实验批次，不新建第二套调度器。worker 全局并发 1；主 Run 槽位唯一，start/cancel/approve 幂等。等待审批期间不持有执行槽位或数据库锁；恢复仍核对检查点并遵守全局执行并发限制，实际执行顺序偏差记录下来。
4. 运行各自独立工作区，接通准备、执行、审批、评测、清理、终态。worker 重启核对所有权与状态，无法证明安全恢复时不自动重放付费/写入步骤。
5. Experiments 页面轮询进度，可取消整个实验或单次 Run，能够进入待审批/失败详情。已接受的执行错误写入 Run，不能只给不可诊断的 HTTP 500。

验收：通过页面跑无模型 Demo 两版本实验，验证双击启动、取消、重启、失败与准备失败记录。不同 Agent/干预方式用 benchmark；controlled 非声明差异不得默默忽略。

### Day 6：分级观测、比较与五页闭环

1. 将前几天采集的证据聚合成统一 Run 报告：能力声明/校验、字段实际完整性、来源、执行与验收状态、覆盖率及关联证据。
2. Run/Trace 按生命周期、调用、上下文、Diff、Tests 展示；事件按平台 sequence 分页，保留原始事件/调用关联。缺失、无此能力、未发生和无效分别呈现，不伪造零值或精确因果时间线。
3. 比较器支持受控模式和多变量 Benchmark；复用已有纯分析/决策逻辑，但不将 Agent/模型的已声明差异一律判成不合法。不可核实的执行身份、测试环境、必需证据仍阻止肯定结论。
4. 统计保留所有已启动 Run；未知/进行中、准备失败、额外尝试单列。资源仅比较同对完整样本；成本缺价格未知，人工等待不猜成 0。无标注不算 Recall。
5. Dashboard、Agents、Benchmarks、Experiments、Run/Trace 导航闭环；复用已有对比与决策组件，支持 JSON/Markdown 导出及历史只读查看。机器结论和人工采用记录分开，复核必须绑定证据，不能借复核修改成绩。

验收：一个真实 L0 Run 没有 Token 仍可验收；Native 的实际 L1/L2 字段能追到证据；明确标记的部分/无效上报 fixture 不进入真实实验统计。live 与 archived 数据不会混算，页面刷新可恢复查看。

### Day 7：集中联调与可演示交付
